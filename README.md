# МП-3.5 «БДТС» — MVP

Веб-приложение модуля «База данных технического состояния оборудования» единой цифровой платформы ДТОиР.
Объём — кликабельный прототип v1.3 на реальном бэкенде: 38 экранов W-0.1…W-8.3, сценарии UC-1…UC-7, правила ТПР (R-\*),
новой концепции (D-\*) и модели ТО v3.8 (V-\*, XSD).


## Состав

| Каталог | Что внутри |
| --- | --- |
| `backend/` | FastAPI, SQLAlchemy 2 (async), Alembic, воркер очередей, XSD v3.8 и валидаторы, mock-адаптеры интеграций, демо-данные, автотесты |
| `frontend/` | React 18 + TypeScript + MobX + Ant Design 5 (Vite), вход через Keycloak (OIDC + PKCE) |
| `infra/` | Keycloak realm (роли, группы, демо-пользователи), Caddy (TLS), init PostgreSQL |
| `docs/` | План, архитектура и интеграции, развёртывание |

## Демо-данные

Интерфейс только на русском языке, в том числе страница входа Keycloak (`supportedLocales: ["ru"]`).
Данные заведены по всем ДЭО (ОРГ_4, ОРГ_6, ОРГ_9): иерархия ТМ/ЕО, задания и результаты ДО во всех статусах, ТО из ИУС ГД,
записи о ТС, расхождения, перечни к планированию и уведомления. В личном кабинете фильтр «ДЭО» пересчитывает виджеты и уведомления.

Полностью завершённые результаты ДО («Результат получен», заполнены все разделы ПЭ и КП):

| Задание | Вид ДО | ДЭО | Объект |
| --- | --- | --- | --- |
| 8 | ТПА | ОРГ_9 | Задвижка клиновая ЗКЛ2 200 (с ЭПБ) |
| 11 | Сосуды и аппараты | ОРГ_9 | Пылеуловитель ПУ-1 |
| 12 | ФА и КГ | ОРГ_6 | АФК 80х35, скв. 1031 |
| 13 | ГРС | ОРГ_4 | ГРС-12 «Северная» (5 ЕО) |
| 14 | ТПА | ОРГ_4 | Узел подключения КС-7 (3 ЕО) |
| 15 | Сосуды и аппараты | ОРГ_4 | Сепаратор С-201 (отклонения на границе допуска, с ЭПБ) |

**Технический отчёт (.docx)** — кнопка «Выгрузить технический отчет» в карточке результата ДО (статусы по ТПР п. 4.4.7).
Отчёт каждый раз формируется заново по текущим данным (`backend/app/services/report_docx.py`) по форме Приложения В.1
Р Заказчик «Исполнительная документация при ДО»: титул с грифом «УТВЕРЖДАЮ» (п. 7.1.7), 15 разделов вводной части (п. 7.1.4 а–п),
ведомость дефектов, выводы со сроком следующего ДО (п. 7.1.5), протоколы по каждому методу контроля, расчёт остаточного ресурса,
перечень НТД и лист согласования из истории результата (п. 7.1.9). Реквизиты организаций, адреса, номера свидетельств о поверке
и ОПО — условные mock-данные.

## Быстрый старт локально (без Docker)

```bash
cd backend && pip install -r requirements.txt && uvicorn app.main:app --reload
```

По умолчанию — SQLite, файлы на диске, вход в dev-режиме (`AUTH_MODE=dev`, токен `dev:<логин>`), демо-данные загружаются автоматически.
OpenAPI: http://localhost:8000/api/docs. Фронтенд: `cd frontend && npm install && npm run dev` (прокси `/api` на :8000), вход — выбор демо-пользователя.

Тесты: `cd backend && pytest` — сквозные сценарии S1–S5 и правила.

## Стенд (Docker Compose)

```bash
sh scripts/init-env.sh
docker compose up -d --build
```
