# Архитектура MVP и интеграции

## Компоненты

```
Браузер ──HTTPS──► Caddy (TLS Let's Encrypt)
                     ├── /        → web      (nginx, SPA React)
                     ├── /api/*   → api      (FastAPI, uvicorn ×2 worker; масштабируется репликами)
                     └── /auth/*  → keycloak (OIDC, realm bdts)
api ─► PostgreSQL 15 (схема — Alembic) · S3 (SeaweedFS) · RabbitMQ · Redis
worker ─► очередь bdts.jobs (импорт xlsx) · очередь bdts.outbox (доставка событий в адаптеры) · переотправка раз в 30 с
```

Все сервисы приложения stateless (сессия — JWT), поэтому горизонтально масштабируются: `docker compose up -d --scale api=3`
или Deployment в Kubernetes. Состояние — только в PostgreSQL, S3 и брокере. Длительные операции выполняются асинхронно в воркере.
Наблюдаемость: `/api/health`, `/api/ready`, `/api/metrics` (Prometheus), журнал аудита `audit_log`.

## Слои бэкенда

| Слой | Каталог | Назначение |
| --- | --- | --- |
| API | `app/api` | REST-контракт (OpenAPI `/api/docs`), DTO, проверка роли (`require(action)`) |
| Сервисы | `app/services` | Бизнес-логика: статусные машины Б301/Б303/ТО, правила R-\*/D-\*, раскладка ТО → Б316, аналитика |
| Модели | `app/models` | ORM; JSONB для данных разделов ДО и разобранного XML |
| Интеграции | `app/integrations` | Порты (`ports.py`) и адаптеры; выбор — переменными `ADAPTER_*` |
| ТО v3.8 | `app/services/tr_xml.py`, `app/xsd/` | XSD-проверка (D-TO-06), разбор, валидаторы V-\* (L1→Block, L2→Warn, L3/L5→Info) |

Права проверяются на сервере по матрице «роль → действия» (`app/permissions.py`) и по признаку ДЭО (claim `deo`):
пользователь с атрибутом ДЭО видит только данные своего ДЭО. Интерфейс скрывает кнопки по той же матрице, но доверять ему сервер не обязан.

## Интеграции

| Поток (интеграции.txt) | Порт | Сейчас | Как подключить реальную систему |
| --- | --- | --- | --- |
| 1. Аутентификация и авторизация | Keycloak OIDC | Keycloak с демо-пользователями | В Keycloak: User Federation → LDAP (каталог заказчика), Group mapper «группа LDAP → роль BDTS.\*», атрибут `deo` из LDAP. Код не меняется |
| 2.1. Пообъектный план | `PlanSource.fetch_plan(year, deo)` | `MockPlanSource` (строки в формате ХР.xlsx) + загрузка файла ХР.xlsx | Реализовать адаптер REST/очереди ФМ-5.1, зарегистрировать в `registry._ADAPTERS["plan"]`, `ADAPTER_PLAN=<имя>` |
| 2.2. Атрибуты ТМ/ЕО из МП-3 «БДО» | `BdoClient` | Локальная реплика ТМ/ЕО + `MockBdoClient` | Адаптер REST МП-3 / событий RabbitMQ; `sync_hierarchy()` обновляет реплику |
| 3.1. Передача ТО | `ReportSink.send_report` | Журнал обменов | Адаптер ИУС ГД / СЭД; вызывается из outbox-события `report.accepted` |
| 3.2. Сведения по ДО | `DiagnosticsSink.send` | Журнал обменов | Адаптер МП-1/ТОиР; события `diag.defects`, `plan.list` |
| Задачи ПС-0 (memo) | `Ps0Client.create_task` | Номер задачи (mock) | Адаптер ПС-0 |
| Оповещения | `Notifier.send` | Колокольчик в UI, e-mail не отправляется | SMTP-адаптер, правила — W-7.1 |

Исходящие обмены идут через transactional outbox (`outbox_event`): событие пишется в одной транзакции с бизнес-изменением,
воркер доставляет его в адаптер с повтором (до 5 попыток) и идемпотентным ключом. Журнал обменов — W-8.1 и W-7.1 «Интеграции».

## Принятые допущения

См. `docs/PLAN.md`, раздел 5. Кратко: статусы ТО по «Описанию процессов_2» (OQ-10), отправка ТО в ДЭО блокируется
до сопоставления всех ЕО (OQ-14), L1 → Block (OQ-07), лимит файла 50 МБ (OQ-21), роль администратора `BDTS.ADMIN` (OQ-29).

## Отступления от целевого стека платформы

- Бэкенд на Python/FastAPI (решение заказчика MVP) вместо .NET 8 — контракт API (OpenAPI) и модель данных переносимы.
- Объектное хранилище — SeaweedFS (S3 API): образы MinIO community больше не публикуются. Бэкенд работает по протоколу S3,
  замена на MinIO/Ceph/облачное S3 — изменение `S3_ENDPOINT`.
- Сборщик фронтенда — Vite (быстрее webpack), стек компонентов совпадает с платформой: React 18, TS, MobX, Ant Design.
