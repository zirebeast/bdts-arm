# План разработки MVP МП-3.5 «БДТС»

Версия 1.0 · 25.10.2026

## 1. Цель и границы

MVP веб-приложения модуля МП-3.5 «База данных технического состояния оборудования» (ЕЦП ДТОиР)
в объёме кликабельного прототипа v1.3 (`дизайн/версия 3/3_5_v2.tsx`), но на реальном бэкенде:
данные хранятся в БД, статусные модели и правила (R-*, D-*, V-*) проверяются на сервере,
файлы — в S3-хранилище, роли — из Keycloak.

Интеграций пока нет, поэтому все внешние системы подключены через **порты (интерфейсы) и mock-адаптеры**.
Замена mock на реальный адаптер — смена переменной окружения и реализация одного класса.

Входит: 38 экранов W-0.1 … W-8.3 (кроме витрины UI-Kit), шесть сценариев UC-1…UC-6 и UC-7 (входящие интеграции).
Не входит: планшетное приложение ГД, печатные формы ГОСТ/РТН, интерфейсы СУИА/МП-1/МП-2.

## 3. Архитектура

```
Браузер ──HTTPS──► Caddy ──► /            frontend (nginx, статика SPA)
                        ├──► /api/*       backend API (FastAPI, N реплик)
                        └──► /auth/*      Keycloak (OIDC)
backend API ──► PostgreSQL · Redis · MinIO · RabbitMQ ──► worker (импорт, XSD, outbox → адаптеры)
```

Слои бэкенда: `api` (маршруты, DTO) → `services` (бизнес-логика, статусные машины, правила) →
`models` (ORM) / `integrations` (порты + адаптеры). Права проверяются на сервере по матрице
«роль → действия» и по признаку ДЭО (разграничение данных, табл. 4 ТПР).

### Порты интеграций (mock-адаптеры в MVP)

| Порт | Направление | Источник требований | Mock |
| --- | --- | --- | --- |
| `IdentityProvider` | вход | интеграции.txt п.1, ТПР (LDAP) | Keycloak с демо-пользователями |
| `PlanSource` | вход | п.2.1 «пообъектный план» (ФМ-5.1 / АСУ ТОиР) | фикстура строк ПП в формате `ХР.xlsx`; загрузка xlsx |
| `BdoClient` | вход | п.2.2 атрибуты ТМ/ЕО из МП-3 «БДО» | локальная реплика ТМ/ЕО + фикстура каталога ЕО |
| `ReportSink` | выход | п.3.1 передача ТО | журнал обменов + копия пакета в S3 `outbox/` |
| `DiagnosticsSink` | выход | п.3.2 сведения по ДО (дефекты, перечни) | журнал обменов |
| `Ps0Client` | выход | memo: задачи на добавление ЕО/ТМ в БДО | журнал + номер задачи |
| `Notifier` | выход | ТПР Прил. 2 (оповещения) | колокольчик в UI + журнал вместо SMTP |

Все исходящие обмены идут через таблицу outbox и RabbitMQ (гарантированная доставка, повтор, идемпотентность).

## 6. Критерии готовности

- Все экраны открываются по ролям, кнопки скрыты/неактивны по статусу и роли, правила проверяются на сервере.
- Сквозные сценарии S1–S5 проходятся без тупиков на демо-данных.
- Загрузка корректного XML проходит XSD v3.8; некорректного — даёт Block с понятным текстом.
- Приложение развёрнуто на ВМ, доступно по HTTPS, переживает перезапуск (данные в томах).
